# 10 — Choose Recovery actions from branch safety

**What to build:** Select purification, rest, or an explicitly permitted Equipment transform according to what makes the next complete visible branch safe, without using a generic local score.

**Blocked by:** 01 — Explicit strategy modes and Boss-aligned run boundaries; 03 — Project route-horizon safety and erosion recoverability; 04 — Enforce Code-family integrity and hard eligibility; 09 — Resolve Event options into exact commitments.

**Status:** complete; implementation and existing evidence verified

Evidence: [`evidence-backed-strategy-modes-10-12-evidence.md`](../../../docs/agents/evidence-backed-strategy-modes-10-12-evidence.md); characterization coverage is also indexed in [`evidence-backed-strategy-modes-17-story-traceability.md`](../../../docs/agents/evidence-backed-strategy-modes-17-story-traceability.md).

- [x] Purification and rest are projected into the next complete visible branch rather than ranked from their immediate deltas alone.
- [x] When only one deterministic choice makes a branch safe, that choice is committed.
- [x] When neither deterministic choice makes any branch safe, automation pauses without pretending to repair it.
- [x] When both preserve safety, rest wins if any active character is below the HP soft floor; otherwise purification wins when erosion is above zero.
- [x] When both deterministic choices have zero marginal value, a stable harmless option is selected.
- [x] Research always rejects random Code transformation.
- [x] Equipment transformation is disabled by default and requires explicit opt-in, a removable hard-excluded held Code, and zero value from both deterministic choices.
- [x] Transform is treated as server-random Recovery flow, never deterministic Code Offer replacement.
- [x] The exact Recovery choice and expected effects remain committed through authoritative reconciliation.
- [x] Tests cover each safety branch, tie rule, zero-value fallback, Research rejection, Equipment opt-in, and transform mismatch.
